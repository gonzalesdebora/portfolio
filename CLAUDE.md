# Case Studies

When writing or rewriting case study copy for `case-studies/*.html`:

- Follow the tone and length modeled in `context/case-study-how-to/` and `context/case-study-example/`. Read both before writing.
- Do not use dashes ("–" en dash or "—" em dash) anywhere in the text. Rewrite the sentence instead (split into two sentences, use a comma, or use "and"/"but").
- Do not use semicolons (";") or colons (":") anywhere in the text. Rewrite the sentence instead (split into two sentences, use a comma, or use "and"/"but"/"including").

# Code Style

The user is learning to code and wants to be able to understand every line written for this project.

- Write beginner-friendly code, matching the level and simplicity of the Codecademy cheatsheets in `code-academy-cheat-sheets/` (HTML elements and structure, CSS visual rules, JavaScript DOM events). Read them if unsure what "beginner level" means for a given language.
- Prefer simple, explicit code over clever, compact, or advanced patterns. Avoid JavaScript/CSS features or techniques a beginner wouldn't have seen yet, unless there's no simpler way to do it.
- Add short comments explaining what non-obvious code does and why, so the user can follow along and learn from it.
- When a change is non-trivial, briefly explain it in plain language, not just make the edit silently.
